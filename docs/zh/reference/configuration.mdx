QitOS 的配置主要分三层：

1. **`AgentModule.run()` 关键字参数**：最常见、最推荐的每次运行配置入口
2. **`Engine` 构造函数参数**：更底层的运行时控制
3. **环境变量**：供应商凭证与模型默认值

## AgentModule.run() 参数

这些参数都可以直接传给 `agent.run(task, ...)`：

<AccordionGroup>
<Accordion title="任务与执行">

- `task`：`str | Task`
- `max_steps`
- `return_state`
- `workspace`
- `env`

</Accordion>

<Accordion title="解析与决策">

- `parser`
- `search`
- `critics`（评估器，可批准、停止或重试当前步骤）
- `stop_criteria`
- `history_policy`

</Accordion>

<Accordion title="追踪与渲染">

- `trace`
- `trace_logdir`
- `trace_prefix`
- `render`
- `theme`

</Accordion>

<Accordion title="钩子与 Engine 透传">

- `hooks`
- `render_hooks`
- `engine_kwargs`
- `**state_kwargs`

</Accordion>
</AccordionGroup>

一个典型例子：

```python
result = agent.run(
    task="Analyse the repository and list all public API functions.",
    workspace="/path/to/repo",
    max_steps=20,
    trace_logdir="./experiment-runs",
    trace_prefix="api-analysis",
)
```

## Engine 构造参数

当你直接构造 `Engine` 时，最常用的参数包括：

- `agent`
- `budget`（预算）
- `validation_gate`
- `recovery_handler`
- `recovery_policy`
- `trace_writer`
- `parser`
- `stop_criteria`
- `branch_selector`
- `search`
- `critics`（评估器）
- `env`
- `history_policy`
- `hooks`（钩子）

`RuntimeBudget` 的常见字段：

```python
@dataclass
class RuntimeBudget:
    max_steps: int = 10
    max_runtime_seconds: Optional[float] = None
    max_tokens: Optional[int] = None
```

## 恢复策略

`RecoveryPolicy` 决定步骤失败后是终止还是重试。`classify_exception()` 在模型驱动的阶段（`DECIDE`、`PROPOSE`、`PLAN`、`FORMULATION`、`INVESTIGATION`）会把以下失败标记为可恢复：

| 失败 | 分类 | 可恢复 |
|---|---|---|
| 流式/读取超时、连接错误、网关重启（`no healthy upstream`、`bad gateway`） | `model_error` | 是 |
| 网关 HTTP `502`/`503`/`504`（`ServiceUnavailableError`、`gateway timeout`、`temporarily unavailable`） | `model_error` | 是 |
| 提供方鉴权失败（HTTP `401`、`Unauthorized`、密钥失效或被轮换） | `model_error`，`details={"auth_error": True}` | 是 |
| 模型调用抛出的其它任何异常（包装为 `LLMCallError`） | `model_error`，`details={"llm_call_error": True}` | 是 |
| 上下文长度溢出 | `model_error`（先尝试响应式压缩） | 是 |
| `ACT` 阶段的工具错误 | `tool_error` | 是 |
| 解析错误 | `parse_error` | 是 |
| 其它异常 | `system_error` | 否——立即以 `unrecoverable_error` 停止 |

只有**连续**的可恢复失败会累计到上限：只要有一步成功，连续计数就会重置。因此一个彻底失效的密钥仍会在重试次数耗尽后终止运行。

重试间隔是渐进式的：第一次重试等待 `QITOS_RECOVERY_BACKOFF` 秒，之后每连续失败一次翻倍，直到 `QITOS_RECOVERY_BACKOFF_MAX`。默认序列为 `1、2、4、8、16、30、30……` 秒。

| 变量 | 默认值 | 用途 |
|---|---|---|
| `QITOS_MAX_RECOVERIES` | `100` | 连续可恢复失败的上限，超过后以 `unrecoverable_error`（`max_recovery_exhausted`）停止 |
| `QITOS_RECOVERY_BACKOFF` | `1.0` | 任意可恢复失败第一次重试的基础等待秒数，之后每连续失败一次翻倍，限制在 `0`–`60`；设为 `0` 表示立即重试 |
| `QITOS_RECOVERY_BACKOFF_MAX` | `30.0` | 渐进式重试间隔的上限，限制在 `0`–`600` |

## 环境变量

常见环境变量包括：

| 变量 | 用途 |
|---|---|
| `OPENAI_API_KEY` | OpenAI / OpenAI 兼容 API 密钥 |
| `OPENAI_BASE_URL` | OpenAI 兼容端点基础 URL |
| `QITOS_API_KEY` | `ModelFactory.from_env()` 可识别的备用密钥 |
| `QITOS_MODEL` | 默认模型 ID |
| `QITOS_MAX_RECOVERIES` | 连续可恢复失败的上限，默认 `100` |
| `QITOS_RECOVERY_BACKOFF` | 任意可恢复失败第一次重试的基础等待秒数，之后每连续失败一次翻倍，默认 `1.0`，限制在 `0`–`60` |
| `QITOS_RECOVERY_BACKOFF_MAX` | 渐进式重试间隔的上限，默认 `30.0`，限制在 `0`–`600` |
| `AZURE_OPENAI_API_KEY` | Azure OpenAI 密钥 |
| `AZURE_OPENAI_ENDPOINT` | Azure OpenAI 端点 |
| `AZURE_OPENAI_DEPLOYMENT` | Azure 部署名称 |
| `AZURE_OPENAI_API_VERSION` | Azure API 版本 |

示例：

```bash
OPENAI_API_KEY=sk-...
OPENAI_BASE_URL=https://api.siliconflow.cn/v1/
```

## 追踪输出目录

默认情况下，`AgentModule.run()` 会把追踪记录写到 `./runs/`：

```text
<trace_logdir>/
└── <trace_prefix>_<YYYYMMDD_HHMMSS_ffffff>/
    ├── manifest.json
    ├── events.jsonl
    └── steps.jsonl
```

你可以通过 `trace_prefix` 覆盖自动生成的前缀：

```python
agent.run(task="...", trace_prefix="experiment-01")
```

然后用：

```bash
qita board --logdir ./runs
```

来查看这些结果。
